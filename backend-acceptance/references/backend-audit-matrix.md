# 后端验收矩阵

| 维度 | 最小问题 | 证据 | 阻断示例 |
|---|---|---|---|
| 业务来源 | 规则来自哪里？实现是否引入未经授权行为？ | 需求/ADR/API/测试映射 | AI 自行加入折扣、默认权限、状态跳转 |
| 输入与状态 | 每个字段的允许域、组合约束、状态顺序是什么？ | schema、负例、状态机测试 | 只校验类型，不校验状态/所有权/范围 |
| 事务 | 原子操作边界在哪里？外部副作用如何补偿？ | DB 日志、隔离级别、失败注入、对账 | 支付在 DB 事务里却无补偿，部分写入 |
| 并发 | 共享不变量如何在多线程/多进程/重启下保持？ | 压测、竞态、锁/唯一键、SQL 计划 | 读改写库存、单机锁、无界 goroutine |
| 幂等 | 同键重试、并发首请求和不同 body 怎么处理？ | 持久化状态、唯一约束、回放测试 | 进程内 Map 或缓存丢失后重复扣款 |
| 授权 | 身份之外，能否操作此对象/字段/状态/租户？ | 多身份请求矩阵和审计日志 | IDOR、批量接口越权、管理员自批 |
| 数据库 | 谓词/排序/连接是否有匹配索引？ | EXPLAIN、真实数据量、p95/p99 | 全表扫描、N+1、深分页、迁移无回滚 |
| 外部依赖 | 超时、重试、限流、熔断、乱序回调如何处理？ | 故障注入、指标、队列重投 | 重试相乘、无界等待、重复副作用 |
| 安全 | 输入、密钥、日志、上传、出站请求是否受控？ | SAST/DAST/依赖扫描+人工反例 | SSRF、注入、路径穿越、敏感信息泄露 |
| 可观测 | 能否定位 request、状态变化、重试和对账差异？ | 日志/trace/metrics 样本 | 只打字符串，缺少关联 ID 和业务指标 |

## 严重级别

- **Blocker**：无法证明核心需求、数据损坏/丢失、可直接越权/扣款、不可回滚上线。
- **Critical**：高概率并发/事务/安全漏洞，或关键失败路径导致重复副作用。
- **High**：可利用的边界缺口、索引/容量风险、跨实例一致性不足，需上线前修复或明确风险接受。
- **Medium/Low**：不影响当前关键不变量但应有 owner、期限和回归测试。

## 结论计算

`准入` 需要：所有 Blocker/Critical 为 0；核心业务、权限、事务、幂等和数据项均有证据；性能和安全扫描的适用范围已说明；剩余 High 有书面风险接受和回滚。任一关键环境不可用、规则来源缺失或反例未执行，结论为 `不准入` 或明确的 `有条件准入`，不能给“无隐藏问题”。

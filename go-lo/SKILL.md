## 选函数前固定契约

| 当前需要 | 重点核对 |
|---|---|
| `Map` / `Filter` / `FilterMap` | 回调参数、是否保序、空值表示、是否需要中间集合；`FilterMap` 的 bool 表示是否保留结果 |
| `GroupBy` / `SliceToMap` | 分组与索引不是同一契约；重复 key 策略、元素顺序与 map 输出顺序分别说明 |
| `Find` 等查找 | 处理返回的 found/ok；未找到与找到零值不能混成一个分支 |
| `Reduce` | 初始累积值、空输入与数值范围；不借重写改变金额精度或溢出行为 |
| 条件/指针 helper | 是否提前求值、nil 与零值是否可互换、返回值是否仍与输入共享对象 |

## 容易改变行为的边界

- 新 slice/map 不等于深拷贝。指针元素、嵌套 map/slice 与回调捕获的对象仍可能共享；`Filter` / `GroupBy` 等返回新容器也不能据此宣称并发安全。
- 保留 nil 与非 nil 空集合的既有契约。官方当前 `Map` 通过 `make` 分配结果，不能假定 nil 输入仍返回 nil；项目版本及 JSON 的 `null` / `[]` 输出要一起核对。
- 官方当前 `SliceToMap` / `Associate` 重复 key 为后者覆盖前者；要求拒绝重复、保留首个或累计时，不能直接替换。map 的遍历顺序不能作为稳定输出，排序需有已确认的输出要求。
- `lo.Ternary` 的两个值参数会先求值，不能保护另一分支的 nil 解引用或副作用。需要惰性分支时用普通 `if`，或先核对当前版本支持的 `TernaryF` 等惰性 API。
- `lo.FromPtr` 等零值回落可能丢失“未提供”的语义；先确认字段是否允许把 nil 等同于零值。`lo.Must` 将错误转为 panic，不用它隐藏请求、任务或依赖调用的可恢复失败。
- 有错误、取消、提前退出、资源释放或部分成功语义时，先确认回调与函数真实返回契约；普通 `Map` 不返回业务 error。`MapErr` 等只在锁定版本确实提供且失败语义符合需求时采用，不为缩短代码吞错或强行套 helper。
- `mutable` 会改变输入；`parallel` 的调度、顺序、并发数量、取消和共享写入须另核对。不能把替换为子包当成等价优化，也不使用固定元素数量断言并行一定更快。

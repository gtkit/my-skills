# Go 代码导航与调用方覆盖

用于被改符号的影响分析，供 `go-review` 与 `go-enterprise-quality` 共用。导航本身只读；重命名、生成或重构仍须在当前代码修改授权与已保存计划范围内执行。

## 先确定查询上下文

- 从真实文件定位声明、包路径、接收者和接口，不能仅凭函数名把同名符号合并。
- 读取相关 `go.mod` / `go.work`、构建标签、平台条件及生成物约定，记录本次覆盖的模块和构建配置。
- 先发现当前工具及其实际能力、版本和文档。gopls/LSP、MCP 或 CLI 的可用入口按环境核实，不臆造工具名、参数或变量；缺失时不自动安装。

## 组合语义与文本证据

1. 工具可用时，对准确声明位置查询定义、引用、实现及调用层次中实际支持的能力。接口变更同时核对实现和使用方，函数值赋值也要沿引用继续读取。
2. 用 `rg` 补查符号、import 路径、路由注册、回调装配、生成源与测试；正则和字符串搜索只产生候选，不等同于完整调用图。
3. 对反射、字符串注册、插件、RPC/HTTP 消费者和仓库外调用方单独列出边界。语义查询不能自动证明这些运行时关系，也不能代表其他构建标签或平台。
4. 逐个读取受影响调用点，核对错误分支、部分成功、返回值含义、ctx 传播和资源/并发归属；不能只统计引用数。
5. 缺少语义工具时，使用 `rg` 与源码追踪完成能做的部分，明确“文本与源码范围内核对”，记录尚未覆盖的接口分派、模块或构建配置，不声称已找到全部调用方。

## 结果怎么记录

| 项目 | 应记录的证据 |
|---|---|
| 符号 | 完整包/类型/方法名与实际声明位置 |
| 查询范围 | 模块、工具与版本、构建标签、GOOS/GOARCH（未核实则标未确认） |
| 调用点 | 实际文件位置、通过接口/函数值/注册调用的路径与分支结论 |
| 覆盖缺口 | 动态调用、未生成产物、其他平台和仓库外消费者 |
| 适配结论 | 已适配 / 无需适配及依据 / 未验证；不以查询成功代替契约验证 |

依据：[gopls 官方功能索引](https://go.dev/gopls/features/)。文档列出的能力不代表当前客户端已经暴露对应工具，实际使用前仍需核对。

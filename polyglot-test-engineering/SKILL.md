# 跨栈测试工程

## 前置必读：拒绝猜测与改动边界

- 每次使用本 skill、恢复任务及执行任何改动前，先实际读取本节、当前运行环境已配置的全局规则，以及目标项目已有的协作规则和错误记录。按已明确的配置入口定位，不猜路径、不硬编码本机目录，不以记忆或摘要替代；必需规则无法读取时停止改动并说明。
- 需求、接口、字段、权限、默认值、路径、工具能力、依赖与兼容结论必须有用户指令、已读取源码/配置、已核实官方资料或真实执行证据。未知保持未确认，先核实；仍不明确就停止依赖该信息的步骤，不凭猜测补全，不重复询问已经明确的要求。
- 修改代码前先完成并落盘方案和逐步计划，写清范围、文件、兼容约束、风险、回滚和验收；只执行获准范围及阶段。计划、候选原因和未执行步骤标为待验证，不能当作事实或已完成结果。
- 只有真实执行并回读后才能报告完成或通过，区分失败、未执行、未验证和不适用；模拟与静态证据不冒充真实链路。纯文档、注释、规则或 skill 说明任务只编辑指定内容并回读，不因本 skill 的流程扩展为测试、构建、同步、打包或 OpenSpec 操作。

用于 Go、PHP、Node/npm、前端和 OpenResty 组成的系统，选择测试层次并形成可审计证据。它编排风险覆盖和环境策略，具体语言写法及最终发布准入交给对应 skill。

## 适用场景

- 从需求、API schema、状态机和依赖拓扑选择单元、契约、集成、E2E 或故障注入测试。
- 设计跨服务数据、权限、重试、超时、并发和恢复测试。
- 排查 flaky、测试数据污染、环境漂移、覆盖率误读和“测试全绿但线上失败”。

## 输入与前置事实

收集需求和业务不变量来源、API/event schema、状态转换、权限/租户矩阵、依赖版本和拓扑、测试环境、可用容器/沙箱、测试数据策略、隐私约束、SLO/性能预算、发布回滚条件。没有需求或契约来源时将对应规则列为未确认，核实前不得补写业务规则，也不能用测试通过代替其来源。

## 按顺序执行

1. **建立风险矩阵**：把用户流程或事件拆成成功、边界、非法、超时、取消、重试、并发、重复提交、越权、数据恢复和资源耗尽场景；为每项指定不变量、测试层次、证据和负责人。
2. **选择最小充分层次**：纯规则优先单元；跨语言字段和兼容性用 contract test；真实数据库、缓存、队列和网关用 integration；关键用户路径用真实浏览器 E2E；超时、节点丢失、重启和网络错误用受控 fault injection。层次选择要写出为什么更低层次不足。
3. **固定契约与版本**：冻结请求/响应、事件 schema、错误码、鉴权和幂等约束；测试兼容的旧/新版本、未知字段、重复投递和乱序。契约不完整时只报告已覆盖部分。
4. **隔离测试数据**：为每个测试或测试组定义租户/资源命名、事务或 schema 隔离、时钟、随机种子和清理责任；禁止依靠模糊 `DELETE` 清理共享数据。敏感数据使用批准的脱敏 fixture。
5. **运行跨栈集成**：按生产路由装配启动网关、PHP/Go/Node 和真实依赖；记录镜像/依赖版本、配置、端口、迁移、seed、时间窗口和日志。缺少外部依赖时失败或标未验证，不用运行时 `skip` 制造假绿。
6. **覆盖故障与恢复**：注入连接拒绝、超时、断流、5xx、限流、重复消息、进程重启、回滚和部分成功，核对幂等、不变量、补偿和可观测性证据。故障注入范围与停止条件必须受控并可恢复。
7. **治理 flaky**：用固定 seed、重跑次数和并发调度确认是否可复现；收集失败日志、trace、环境差异和最小复现。隔离 flaky 只能有负责人、期限、原失败用例和解除条件，不能静默删除或无限重试。
8. **形成准入报告**：汇总命令、工具版本、样本量、通过/失败/未验证项、覆盖缺口、未确认事项、风险等级、修复验收条件和回滚条件；把测试结果与发布 commit 绑定。

## 失败、回滚与降级

- 环境启动或依赖不可用：保留失败日志，相关场景标未验证并列补测条件；核心路径不可测时不要给全绿。
- 数据污染或 schema 迁移破坏：停止后续测试，销毁隔离环境或恢复快照，重新建立 fixture；记录影响范围。
- 故障注入超出停止条件：立即恢复网络/实例/流量，确认健康和数据不变量，再继续或终止实验。
- 测试改动导致误报：回退测试与 fixture 变更，保留原失败证据；修正测试必须补一个能证明旧缺陷会失败的反例。

## 证据记录

每次运行记录 commit、环境、依赖/镜像、命令、退出码、测试层次、用例/样本数、seed、并发参数、覆盖范围、日志/trace/报告路径、失败复现、重跑结果、数据清理和未验证原因。状态使用“通过 / 失败 / 未验证 / 不适用”；单测、mock、截图或静态检查只证明其覆盖范围。

## 完成条件

- 风险矩阵覆盖关键流程、契约、权限、数据、并发、故障和恢复，并标明证据层级。
- 关键跨语言契约和真实依赖路径已运行；不可运行项有明确补测条件和阻断影响。
- flaky 有可复现记录、责任人和期限；测试数据可隔离、清理和重建。
- 报告绑定发布 commit，给出准入建议、剩余风险和回滚验证；没有把覆盖率或全绿直接等同于生产正确。

## 不触发与路由

- Go 的 `testing` API、`-race`、goleak、fuzz、golden、benchmark 和 Gin handler 细节转 `go-testing`。
- 前端浏览器验收、权限、可访问性和性能准入转 `frontend-acceptance`；后端业务不变量、事务、幂等和最终准入转 `backend-acceptance`。
- OpenResty Lua 代码行为转 `openresty-patterns`，网关配置与流量操作转 `openresty-gateway-operations`。
- 发布编排和回滚流程转 `polyglot-release-engineering`；性能预算与压测定位转 `fullstack-performance`。

# 跨栈生产事故响应

## 前置必读：拒绝猜测与改动边界

- 每次使用本 skill、恢复任务及执行任何改动前，先实际读取本节、当前运行环境已配置的全局规则，以及目标项目已有的协作规则和错误记录。按已明确的配置入口定位，不猜路径、不硬编码本机目录，不以记忆或摘要替代；必需规则无法读取时停止改动并说明。
- 需求、接口、字段、权限、默认值、路径、工具能力、依赖与兼容结论必须有用户指令、已读取源码/配置、已核实官方资料或真实执行证据。未知保持未确认，先核实；仍不明确就停止依赖该信息的步骤，不凭猜测补全，不重复询问已经明确的要求。
- 修改代码前先完成并落盘方案和逐步计划，写清范围、文件、兼容约束、风险、回滚和验收；只执行获准范围及阶段。计划、候选原因和未执行步骤标为待验证，不能当作事实或已完成结果。
- 只有真实执行并回读后才能报告完成或通过，区分失败、未执行、未验证和不适用；模拟与静态证据不冒充真实链路。纯文档、注释、规则或 skill 说明任务只编辑指定内容并回读，不因本 skill 的流程扩展为测试、构建、同步、打包或 OpenSpec 操作。

## 适用场景

当生产异常跨越浏览器、OpenResty/Nginx 网关、PHP-FPM/Octane、Go 服务、Redis、数据库或外部依赖时使用。目标是先保护用户和数据，再用可复现证据定位和恢复；不在没有授权时直接执行生产写入、删缓存、改流量、重启服务或迁移数据库。

## 输入与前置事实

建立事故记录：发现时间、影响范围、症状、告警、最近发布/配置/迁移、受影响区域/租户、当前值班人和可用权限。确认观测来源（浏览器 HAR/console、网关 access/error log、PHP-FPM slow/error log、Go 日志/metrics/traces、Redis/DB 指标和依赖状态）。所有时间使用同一时区，凭证和个人数据脱敏。

严重级别、SLO、止损阈值、回滚版本、降级开关和生产操作授权来自现有应急预案或当班负责人。没有来源的判断保持未确认，先通过获准的只读查询核对证据，不据此执行生产变更。

## 分级与沟通

- **高影响**：核心请求大面积失败、数据完整性/安全风险、持续扩大或无可用替代路径。立即建立事件频道和指挥角色，按预案升级。
- **中影响**：部分功能、区域或租户受影响，有稳定绕行路径。指定负责人和时间窗，持续更新影响与证据。
- **低影响**：单点、短暂或有充分缓解，仍需记录和跟踪，避免未验证的修复扩大范围。

级别按当前可核实的影响和既有分级规则确定；证据不足时明确待确认，随证据更新，不以单个指标自动下结论。

## 按顺序执行

1. **确认与止损计划**：用只读查询确认错误率、延迟、流量、状态码、资源饱和、队列积压和数据异常。明确最小止损动作及其授权人；没有授权时只准备命令和影响说明。
2. **保护证据**：记录 request/correlation id、时间窗口、版本、配置摘要、发布 diff、样本请求/响应、日志片段、指标快照和查询语句。保留原始时间顺序，区分观察事实与尚未确认的候选原因。
3. **画链路并分段验证**：从浏览器请求开始，依次验证网关路由/缓存/TLS、PHP-FPM/Go 进程和依赖、Redis、数据库及外部服务。每一步使用最小只读探针，比较成功与失败样本，避免用单点健康检查证明全链路正常。
4. **选择止损**：按批准预案执行限流、关闭 feature flag、切换只读/降级、停止异常消费者、回滚应用/配置或切换流量。每次操作记录授权、开始/结束时间、目标范围、命令和结果；未授权动作保持待执行。
5. **验证恢复**：观察错误率、延迟、业务成功率、数据写入/对账、缓存命中、FPM/Go 资源、Redis/DB 连接和外部依赖。用代表性浏览器和 API 请求复核用户路径；恢复后继续观察批准窗口，防止反弹。
6. **处理数据风险**：若存在重复扣款、丢失、错写或缓存污染迹象，暂停扩大写入并建立对账/补偿方案。补偿脚本、数据库修改或批量缓存动作必须单独评审和授权，先在隔离环境演练。
7. **收口与复盘**：明确恢复时间、残留风险、监控告警、临时开关和负责人；保存时间线、候选原因的验证结果、决策、证据链接和待办。复盘聚焦可验证的触发条件、检测延迟、止损效果和改进责任，不把推测写成根因。

## 失败与回滚

- 止损动作无效或扩大影响：立即停止该动作，按上一个已验证的稳定版本/配置回滚；记录回滚失败点并升级。
- 回滚受数据库 schema、队列载荷或缓存版本阻塞：先恢复兼容读写路径或降级，再执行批准的补偿步骤；不可逆动作不得声称可回滚。
- 观测系统失真或不可用：用独立只读探针、访问日志和用户样本交叉验证，结论标为低置信度。
- 根因未明但服务已恢复：保持临时缓解和更密集监控，创建后续实验与退出条件，不为“恢复”补写未经验证的根因。

## 证据记录

事故记录至少包含级别和影响、时间线、发布/配置/迁移、查询和命令、日志/指标/trace/HAR 摘要、事实与未确认事项表、授权与操作结果、回滚/降级点、恢复验证、数据风险、未验证项和复盘待办。生产载荷、token、Cookie、密钥和个人数据必须脱敏或只保留引用。

## 完成条件

用户影响已停止或有明确剩余风险，数据完整性检查有结果，临时缓解和回滚点可追溯，关键链路在批准窗口内恢复，所有未知项和后续责任人已记录。事故结案不等于根因已证明；根因、修复和预防措施需以复盘证据更新。

## 不触发与路由

- 只做 Linux、Kubernetes、网络、Prometheus、SLO 或云基础设施判断：路由到 `senior-devops-engineer`。
- 只排查 Go 进程生命周期、探针或服务间调用：路由到 `go-microservice`；Go 代码质量问题追加 `go-enterprise-quality`。
- 只做 PHP/Laravel 运行时判断：路由到 `senior-php-engineer`；PHP 交付门禁路由到 `php-enterprise-quality`。
- 只做 OpenResty Lua 阶段/API 代码：路由到 `openresty-patterns` 或 `senior-openresty-engineer`；网关配置和流量操作追加 `openresty-gateway-operations`。
- 只做接口契约、跨语言字段或兼容性：路由到 `cross-stack-api-contract`。
- 只做跨语言 request ID、trace、日志和告警关联：路由到 `cross-stack-observability`。

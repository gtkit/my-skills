# Go 任务路由

## 前置必读：拒绝猜测与改动边界

- 每次使用本 skill、恢复任务及执行任何改动前，先实际读取本节、当前运行环境已配置的全局规则，以及目标项目已有的协作规则和错误记录。按已明确的配置入口定位，不猜路径、不硬编码本机目录，不以记忆或摘要替代；必需规则无法读取时停止改动并说明。
- 需求、接口、字段、权限、默认值、路径、工具能力、依赖与兼容结论必须有用户指令、已读取源码/配置、已核实官方资料或真实执行证据。未知保持未确认，先核实；仍不明确就停止依赖该信息的步骤，不凭猜测补全，不重复询问已经明确的要求。
- 修改代码前先完成并落盘方案和逐步计划，写清范围、文件、兼容约束、风险、回滚和验收；只执行获准范围及阶段。计划、候选原因和未执行步骤标为待验证，不能当作事实或已完成结果。
- 只有真实执行并回读后才能报告完成或通过，区分失败、未执行、未验证和不适用；模拟与静态证据不冒充真实链路。纯文档、注释、规则或 skill 说明任务只编辑指定内容并回读，不因本 skill 的流程扩展为测试、构建、同步、打包或 OpenSpec 操作。

只负责选择当前任务需要的工程指导，不实现业务，不新增阶段或审批流程。已明确的单一专题直接进入对应 skill；路由完成后不递归加载本 skill，也不预读整个技能库。

## 选择方法

1. 根据用户本次要交付的结果区分解释、方案、审查、实现、质量验证和生产操作。保留已有授权与阶段边界；用户转为非代码请求时不续跑旧代码任务。
2. 选择一个主 skill，仅在当前代码或契约确实涉及其他领域时叠加专项。只读对应任务的参考，不因出现 Go、后端或测试等泛词加载整套门禁。
3. 在需要项目事实时读取已有规则、源码、`go.mod` / `go.work` 与依赖版本。沿用已确认的日志、错误模型、目录与接口；技能默认示例不构成迁移授权。
4. 按实际可发现的名称和资源定位技能，不猜安装路径。缺少某个技能或工具时，记录对应缺口并继续独立可完成的工作；不自动安装，也不把该项标为已执行。

## 按当前任务选择

| 当前请求 | 主入口 | 按涉及范围追加 |
|---|---|---|
| 解释语法、API、输出格式或现有代码 | 直接回答；需要版本核对时读 `use-modern-go` | context 语义读 `go-context`；不启动代码质量门禁 |
| 编写或修改 Gin handler、中间件、DTO | `go-gin-api` | 错误映射读 `go-error-handling`；确实访问 DB、事务或鉴权时再读对应专项 |
| goroutine、channel、锁、并发退出或泄漏 | `go-concurrency` | 涉及取消与 deadline 读 `go-context`；时间/并发测试写法读 `go-testing` |
| 查询、连接池、迁移、事务或幂等写入 | `go-database-patterns` | 并发扣减、事务与补偿读 `go-data-consistency`；取消边界读 `go-context` |
| 服务启停、HTTP/gRPC 调用和 deadline 传播 | `go-microservice` | 预算与重试策略读 `go-stability-engineering`；跨客户端契约变更读 `cross-stack-api-contract` |
| 审查现有 Go 文件、diff 或 PR | `go-review` | 调用方定位按其代码导航参考；按发现的风险读取专项，不自动进入实现或交付门禁 |
| 当前已授权代码修改后的验证、提交前质量检查 | `go-enterprise-quality` | 按改动深度选择检查；测试实现读 `go-testing`，CI 配置读 `go-engineering-governance` |
| 性能退化、CPU/内存/锁/延迟优化 | `go-performance` | 先按指标取基线和匹配的 profile；跨浏览器、网关与 DB 的问题读 `fullstack-performance` |
| 本地 panic、错误结果或不稳定测试 | 按证据选择 `go-review`、`go-concurrency` 或 `go-testing` | 从最小复现和调用链核对开始；只有性能证据需要时读 `go-performance` |
| 架构选型、服务边界、容量或方案评审 | `senior-go-engineer` | 要求方案文档或 ADR 时读 `tech-design-review`；不因此修改项目目录或架构 |
| 生产故障定位与止损 | `incident-response` | 再按链路选择 Go 专项；操作、压测、切流和消息发送遵守本次授权 |
| 后端发布准入、跨栈契约或联合发布 | `backend-acceptance`、`cross-stack-api-contract` 或 `polyglot-release-engineering` | 按用户要求的交付物选一个主入口；普通 handler 改动不自动升级为联合发布 |

实际编写或审查 Go 代码时，按 `use-modern-go` 核对项目版本；这不授权替换无关旧代码。Redis、MQ、缓存、实时推送或安全任务已有明确专题时，直接选对应 `go-*` skill，无需先加载本表所有入口。

## 完成条件

- 所选技能能解释与当前任务的关系；额外参考只在对应风险出现时读取。
- 只读问答与文档维护没有启动测试、构建、旧任务收尾或外部写入。
- 已授权实施与回归测试不重复索要同一授权；尚未授权的阶段不自动执行。
- 交付说明区分文件已改、检查已运行、业务已验证和安装已生效，缺少证据的项目保持未验证。

本路由是指导文本，不是自动拦截机制；自动发现、技能选择与实际完成质量需要在目标平台单独观察，不能以路由表存在代替运行证据。

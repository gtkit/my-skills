# Viper 配置专项

## 前置必读：拒绝猜测与改动边界

- 每次使用本 skill、恢复任务及执行任何改动前，先实际读取本节、当前运行环境已配置的全局规则，以及目标项目已有的协作规则和错误记录。按已明确的配置入口定位，不猜路径、不硬编码本机目录，不以记忆或摘要替代；必需规则无法读取时停止改动并说明。
- 需求、接口、字段、权限、默认值、路径、工具能力、依赖与兼容结论必须有用户指令、已读取源码/配置、已核实官方资料或真实执行证据。未知保持未确认，先核实；仍不明确就停止依赖该信息的步骤，不凭猜测补全，不重复询问已经明确的要求。
- 修改代码前先完成并落盘方案和逐步计划，写清范围、文件、兼容约束、风险、回滚和验收；只执行获准范围及阶段。计划、候选原因和未执行步骤标为待验证，不能当作事实或已完成结果。
- 只有真实执行并回读后才能报告完成或通过，区分失败、未执行、未验证和不适用；模拟与静态证据不冒充真实链路。纯文档、注释、规则或 skill 说明任务只编辑指定内容并回读，不因本 skill 的流程扩展为测试、构建、同步、打包或 OpenSpec 操作。

## 使用范围与版本

- 适用于明确使用或评估 `github.com/spf13/viper` 的任务。先读取项目配置入口、结构体、示例文件、`go.mod` 与实际版本；评估或解释请求不等于安装/升级、迁移字段或开启热重载的授权。
- 沿用项目目录、键名、环境变量前缀与错误契约，不生成另一套配置系统。只有命令树或 Cobra flags 也在本次范围内时再读 `go-cobra`；服务只用 Viper 时不引入 Cobra。
- 官方主分支和在线文档只提供核对入口，具体 API、错误类型与实验开关按锁定版本确认；不以 `@latest` 代替版本决策。

## 配置来源与绑定

- 为受影响 key 列清字段用途、文件键、env 名、flag、默认值、空值回落和约束；实际读取、结构体 tag、示例与说明保持一致。字段、默认值和必填性没有依据时保留未确认，不自行补值。
- 官方优先级为显式 `Set` → 已设置的 flag → env → 配置文件 → 远端 KV → `SetDefault`。未设置 flag 的默认值还有最终回落路径；不能认定只要绑定 flag 就覆盖 env/文件，须核对版本实现与 flag 是否 Changed。
- 不用 `Set` 批量装载 flag 默认值或普通默认配置，它会覆盖更低优先级来源。检查 `BindPFlag` / `BindPFlags` 的实际 flag 实例、作用域及返回错误，在配置首次被消费前完成绑定。
- env 按项目约定决定是否使用 `SetEnvPrefix`、`SetEnvKeyReplacer`、`AutomaticEnv` 或显式 `BindEnv`；不为简单映射强制启用全局自动扫描。键名大小写规则与 env 名大小写分别核对。
- 默认空 env 被当作未设置并继续回落；`AllowEmptyEnv` 会改变该契约。空字符串、`false`、`0`、未设置分别处理，不能用“非零才覆盖”实现优先级。env 值在读取时解析，不假定初始化后已冻结。
- `AutomaticEnv` 能供 `Get*` 查询，不代表所有未登记 key 都会进入 `Unmarshal`；按项目版本核对已知 key 的来源、显式绑定及相关选项。不能靠读取一个字符串就宣称最终结构体已加载成功。

## 加载、类型与失败

- 先确认配置文件是否必须。只有契约允许的文件缺失才可回落；显式指定文件、权限错误、语法错误及其他加载失败按项目错误契约处理，不能一律当成“可选文件不存在”。
- 用与字段一致的 `mapstructure` tag，处理 `Unmarshal` 的返回错误，再做必填、类型、范围、单位与跨字段校验。`Get*` 的零值不证明字段存在、格式正确或通过业务校验。
- 调用 `Sub` 后检查 nil；配置覆盖不要想当然地视为递归合并，尤其集合、嵌套对象和带分隔符的键。规则以已锁版本和项目约定为准。
- 配置解析与业务使用分开：业务消费已校验的配置值；不要在各层散落全局 `viper.Get*`。新增代码优先由现有装配边界传递实例或配置，不据此重构未获准的目录/依赖方向。
- 不记录未脱敏的 `AllSettings`、完整环境变量或密钥。`WriteConfig` 等持久化操作须有对应写入授权，不因读取配置而自动修改用户或项目配置文件。

## 热重载与隔离

- Viper 实例不能被无同步地并发读写。不要只加 `WatchConfig` 就宣称可安全热更新；核对 watcher 写入、回调与读取的归属。
- 确需重载时，由明确的配置管理边界独占/同步实例访问；构造并校验完整新快照，再按已确认方案替换业务读取的不可变快照。失败保留旧配置，敏感或不可热更新字段按既有重启策略处理；相关并发代码再读 `go-concurrency`。
- 新代码及测试需要隔离时使用独立 `viper.New()` 实例，避免全局状态与 `Reset` 影响其他调用方。env 测试遵守 `go-testing` 的进程环境隔离约束，不因维护本文自动启动测试。

## 当前获准代码任务的验收重点

只按本次变更覆盖来源组合、显式 flag 的 false/0、空 env、env-only 结构体字段、缺失/损坏文件、类型错误及默认回落；涉及重载时再验证失败保留旧快照和并发读写。说明哪些已实际验证，不把“配置能读”当作最终业务配置正确。

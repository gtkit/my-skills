# 前端验收矩阵

| 维度 | 至少要有的证据 | 阻断条件 |
|---|---|---|
| 需求/业务 | 需求条目→页面状态→API→测试的映射 | 规则没有来源，或关键流程无测试 |
| 构建/类型 | 固定 commit、Node/包管理器版本、lockfile、typecheck/build 日志 | 构建失败、依赖漂移、secret 进入包 |
| 交互 | 真实浏览器主流程、空态、边界、重复点击、刷新、返回、断网 | 关键按钮/表单/路由无法完成或状态丢失 |
| API | 真实或契约环境的请求/响应、错误码、超时和取消 | mock 通过但真实契约未知 |
| 权限 | 不同用户、租户、资源所有者、状态的请求重放 | 只隐藏 UI，服务端仍可越权 |
| 安全 | XSS/URL/iframe/postMessage/token/CSP 检查与结果 | 不可信 HTML、密钥泄露、token 可被脚本直接读取 |
| 数据 | 金额、时间、精度、分页、缓存、乐观更新回滚 | 重复提交或失败后前后端数据不一致 |
| 性能 | 目标设备 p75 LCP/INP/CLS、JS/图片预算、瀑布和长任务 | 超预算无解释，或仅以 Lighthouse 代替真实交互 |
| 可访问性 | 键盘、焦点、读屏、语义、错误播报、对比度 | 关键流程无法键盘完成或错误不可感知 |

## 计分规则

对外报告必须同时给出数量和等级：`通过/适用项`、`失败`、`未验证`。覆盖率按需求和风险项计算，不能把“不适用”或未验证计入通过。关键流程、权限、数据一致性任何一项未验证，整体最多“不准入”。

## 复现记录

每个失败项保留环境、commit、账号/租户、输入、操作步骤、实际/期望结果、网络请求、截图或日志、严重级别和修复后的重测条件。截图只作辅助证据，不能替代请求和状态证据。

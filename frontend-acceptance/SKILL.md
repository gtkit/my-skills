# 前端项目验收与风险准入

## 核心结论

验收是基于证据的风险判断，不是“能构建”或“截图正常”。先画需求→页面→状态→API→权限→数据的追踪矩阵，再按风险执行静态、自动化、浏览器和联调检查。没有环境或证据就标记 **未验证**，不能写成通过。

## 证据状态

每个验收项只能是：

- **通过**：命令/测试/浏览器步骤/接口响应等证据可复现，且覆盖了适用边界。
- **失败**：出现可复现的错误、越权、数据错乱、性能超预算或安全问题。
- **未验证**：工具、后端、浏览器、测试数据或需求来源缺失。
- **不适用**：写出判定理由；不能用“不知道”替代。

“构建通过”“单测通过”“截图正常”只证明对应局部，不提升其他项的状态。

## 验收流程

1. **范围与事实**：读取 README/需求/接口 schema/权限矩阵/环境说明/迁移和历史缺陷。把 AI 新增的业务规则与需求逐条对照；没有来源的折扣、默认值、状态跳转、权限例外和自动重试列为风险。
2. **追踪矩阵**：对每个用户流程记录入口、状态、请求、响应、错误、权限、租户/用户隔离和持久化结果；标出可用代码、待修代码、无效代码和未覆盖代码。
3. **静态与构建**：运行项目规定的 install/lockfile 检查、类型检查、lint、构建、依赖/secret 扫描和包体预算。记录版本、命令、退出码与日志位置。
4. **行为测试**：覆盖成功、空值、边界、非法输入、超时、断网、401/403/404/409/429/5xx、重复提交、刷新/返回、并发点击和租户切换。优先 Playwright 等真实浏览器测试，辅以 Vitest/Testing Library。
5. **安全与权限**：检查 XSS/v-html/不可信 URL、CSP、token 存储、CSRF 协同、`postMessage`、越权 UI 与服务端授权缺口。用不同用户、租户、资源所有者和状态重放请求；隐藏按钮不算授权。
6. **数据与一致性**：核对金额/时间/时区/精度、分页和排序稳定性、乐观更新回滚、缓存失效、重复提交结果以及前后端 schema 一致性。
7. **性能与可用性**：使用目标环境测量 p75 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1（或项目明确预算）；检查首屏包体、长列表、请求瀑布、取消、重渲染、错误恢复、键盘焦点和屏幕阅读器路径。
8. **准入决策**：Blocker/Critical 任一存在，或关键流程/权限/数据项未验证，结论为 **不准入**。High 风险必须修复或有明确风险接受者、期限和回滚方案；只剩可追踪 Low 才可准入。

## 最小报告

```text
范围：应用/版本/环境/commit
需求覆盖：已验证 X/Y；未验证 Z；未授权规则 N
构建与静态：命令、版本、结果、证据路径
关键流程：通过/失败/未验证（逐条给复现步骤）
安全/权限/租户：证据与风险等级
数据/并发/错误恢复：证据与风险等级
性能/可访问性：指标、样本、预算
结论：准入 / 有条件准入 / 不准入
阻断项：问题、影响、修复验收条件、负责人
限制：不可访问的环境、未运行的测试、未知业务规则
```

## 防止误审

- 不因 AI 代码“看起来合理”而补写需求；需求覆盖率要以来源和测试为准。
- 不把 mock、截图、静态 grep 或单一浏览器当作真实后端、跨浏览器、权限或并发证据。
- 任何“全部覆盖”“没有漏洞”“生产安全”结论必须有范围、工具版本、样本和剩余未知项，否则降级为未证实。
- 前端验收发现服务端责任（授权、事务、幂等、CSRF）时，建立后端阻断项并调用 `backend-acceptance`，不要用前端隐藏控件代替修复。

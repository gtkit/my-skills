# Vue 前端生产开发

## 前置必读：拒绝猜测与改动边界

- 每次使用本 skill、恢复任务及执行任何改动前，先实际读取本节、当前运行环境已配置的全局规则，以及目标项目已有的协作规则和错误记录。按已明确的配置入口定位，不猜路径、不硬编码本机目录，不以记忆或摘要替代；必需规则无法读取时停止改动并说明。
- 需求、接口、字段、权限、默认值、路径、工具能力、依赖与兼容结论必须有用户指令、已读取源码/配置、已核实官方资料或真实执行证据。未知保持未确认，先核实；仍不明确就停止依赖该信息的步骤，不凭猜测补全，不重复询问已经明确的要求。
- 修改代码前先完成并落盘方案和逐步计划，写清范围、文件、兼容约束、风险、回滚和验收；只执行获准范围及阶段。计划、候选原因和未执行步骤标为待验证，不能当作事实或已完成结果。
- 只有真实执行并回读后才能报告完成或通过，区分失败、未执行、未验证和不适用；模拟与静态证据不冒充真实链路。纯文档、注释、规则或 skill 说明任务只编辑指定内容并回读，不因本 skill 的流程扩展为测试、构建、同步、打包或 OpenSpec 操作。

## 定位

负责把已确认的需求和 API 契约落成可运行、可测试、可维护的 Vue 3 + JavaScript/TypeScript 代码。它指导实现，不替代 `senior-frontend-engineer` 的架构判断，也不替代 `frontend-acceptance` 的交付验收。

## 先确认事实

开始改代码前先读 `package.json`、锁文件、`tsconfig`、Vite/Nuxt 配置、路由、状态、API 层、现有测试和项目约定。把信息分为：

- **已证实**：需求、接口 schema、后端实现、迁移、现有测试或运行结果直接支持的事实。
- **待确认**：接口字段、权限矩阵、错误码、分页/排序、租户边界、SSR 运行时等缺失信息。
- **待执行/待验证**：计划中的步骤和验收目标，不能当作已实现事实；缺少依据的事实保持未确认，不以推测补全业务规则。

遇到未知业务规则时，先保留最小行为并指出阻塞项；不要自行增加 VIP、折扣、默认权限、隐式重试或状态迁移。

## 实现顺序

1. **边界**：明确页面/组件输入输出、路由参数、权限、租户/用户上下文、加载/空态/错误态，以及服务端负责的校验。
2. **状态**：服务端数据用查询缓存层；本地 UI 状态用组件或 Pinia；能由现有状态推导的值不要复制进另一个 state。URL 能表达的筛选、分页和排序放 URL。
3. **组件**：组件只拥有自己的交互和展示职责；跨页面副作用放 composable/service；不要在模板中执行网络请求、修改共享对象或写复杂业务规则。
4. **类型与契约**：TypeScript 项目开启严格检查并让请求/响应类型来自 schema 或适配层；JS 项目用 JSDoc、运行时校验和显式边界。外部 JSON 先解析/校验，再进入领域模型。
5. **异步**：每个可取消请求传递 `AbortSignal`；变化中的查询用请求序号或查询库保证旧响应不能覆盖新状态；切换租户、登出、清空筛选和卸载都要使旧请求失效。401 刷新令牌最多单飞一次，刷新失败清理会话并回到登录，不循环重试。
6. **表单**：客户端校验只改善体验，服务端校验才是约束；提交按钮、重复提交、网络超时、服务端字段错误和恢复重试都要有明确状态。金额、库存、权限、状态转换不能由前端决定。
7. **测试**：先写行为测试，再实现。用 Vitest/Testing Library 测状态与可访问交互，用 Playwright 测高价值路径；异步场景至少覆盖过期响应、取消、401、重复提交、租户切换和卸载。

## 生产安全与性能底线

- 不把不可信字符串当 Vue 模板；谨慎使用 `v-html`，富文本必须使用经过审计的 sanitizer，并限制 URL scheme、iframe 来源和 `postMessage` origin。
- 不把密钥放入 `VITE_*` 或其他会打进浏览器包的变量；优先 HttpOnly/Secure/SameSite cookie，并和后端约定 CSRF 防护。
- 不在渲染期产生随机数、当前时间或浏览器专属分支；SSR/水合数据必须可复现。
- 为图片/媒体保留尺寸，首屏资源不要盲目 lazy；路由和重资源按需切分；长列表虚拟化；用真实 p75 的 LCP/INP/CLS 和包体预算验证性能。
- 交互元素使用原生语义元素，表单控件有 label，键盘焦点、错误播报、减少动画和对比度纳入行为测试。
- 组件卸载时清理定时器、订阅、事件监听、WebSocket 和在途请求；避免把“丢弃结果”误当成“取消请求”。

## 交付前自查

- [ ] 所有需求字段和状态转换都有来源；未确认项已列明阻塞的步骤或待验证条件，不以假设补全。
- [ ] API 错误、超时、取消、重试、401 和竞态都有用户可理解的结果。
- [ ] 权限和租户隔离在后端强制，前端只负责显示和减少无效操作。
- [ ] 关键路径有行为/E2E 证据；`build`、类型检查、lint、测试结果可复现。
- [ ] 生产环境配置、CSP/安全头、source map、依赖锁文件和包体预算已核对。
